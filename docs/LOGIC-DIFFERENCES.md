# Различия в логике между четырьмя сайтами

Разбор того, что реально лежало в присланных архивах, где логика четырёх
источников расходилась и как расхождения разрешены в объединённой версии.

---

## 0. Что было в архивах

| Архив | Что внутри | Состояние |
|---|---|---|
| `frontend.zip` | Зеркало `coddb.app` с патченной страницей `/warpets` и собственным `optimizer.js` (81 КБ) | **Конструктор — целиком рабочий.** Остальные страницы — пустые оболочки |
| `sites.zip` | HTTrack-зеркала `coddb.app` и `codfan.com` | `coddb.app` — только главная. `codfan.com` — **ничего** |
| `callmainworkingdata.zip` | Проект `call-main` («Tamaris War Stats») на TanStack Start + React 19 | Полноценное приложение с готовой выгрузкой данных |

Итого объединять было **три** сайта, а не четыре.

### codfan.com не скачался

В `sites.zip/codfan-full/` лежит только кэш HTTrack с одним файлом —
`robots.txt`, 895 байт. Файл `new.txt` (306 байт) содержит ровно одну строку
загрузки. Ни одной HTML-страницы. Судя по логу `doit.log`, обход стартовал
`https://codfan.com/ -O "C:\sites\codfan-full" +*.codfan.com/*` и остановился
сразу после `robots.txt`, то есть сайт закрыт для краулеров либо отдаёт
контент только через JavaScript.

**Что делать:** снять зеркало заново — так же, как снимался конструктор, через
Playwright (`mirror.mjs` из `frontend.zip`), а не HTTrack. Тогда JS отработает
и страницы сохранятся. Пришлите архив — раздел добавится.

### У coddb.app потерялась вся логика, кроме конструктора

14 чанков страниц сохранились **нулевого размера**:

```
pages/index            pages/login           pages/guides
pages/builds           pages/calendar        pages/decree
pages/rowplanner       pages/db/heroes       pages/db/artifacts
pages/calculators/training   .../healing     .../speedup
.../resources                .../heroes
```

Плюс 9 общих чанков тоже пустые. Целиком уцелела только страница
`/warpets` — 240 КБ бандла (патченного, с экспортом `window.__warpetOptimizerAPI`)
и `optimizer.js`. Из данных выжил `api/heroes.json` — 51 герой со всеми навыками.

Поэтому объединять «логику калькуляторов coddb.app» было физически не с чем.

## 1. Язык

| Сайт | Как хранил |
|---|---|
| Конструктор питомцев | `localStorage['warpet-language']` + параметр `?lang=ru\|en`. Переключатель в двух местах: в своей навигации и в панели оптимизатора |
| Tamaris War Stats | `localStorage['tws.lang']`, ключ отдельный, значения те же |
| Остальной coddb.app | Языка не было вообще — только английский |
| codfan.com | Неизвестно |

**Расхождение:** два разных ключа в localStorage, два независимых
переключателя, третий сайт вообще без переводов.

**Как решено.** Один переключатель RU/EN в шапке. Выбор пишется в cookie
`kc_lang` (сервер читает её, чтобы отдать `<head>` на нужном языке ещё до
запуска JS) и дублируется в `localStorage['kc.lang']` и в `?lang=`. Во
встроенный конструктор язык прокидывается через `?lang=` — то есть его
собственный механизм не сломан, просто им управляет шапка. Дублирующийся
переключатель внутри конструктора скрыт (`warpets/embed.js`).

Канонические имена питомцев и навыков остались английскими — как и в
оригинальном оптимизаторе, чтобы совпадать с игровой базой.

## 2. Аккаунты и админка

| Сайт | Что было |
|---|---|
| coddb.app | Страница `/login` существовала, но её чанк пустой — как работала авторизация, установить нельзя |
| Конструктор | Аккаунтов нет. Всё состояние — в `localStorage` |
| Tamaris War Stats | Аккаунтов нет. Пункт меню «Админ» вёл на `/admin/import` — **импорт CSV вообще без авторизации**: кто угодно мог открыть и залить данные |

**Расхождение принципиальное:** у одного сайта авторизация неизвестна, у двух
других её нет, а «админка» третьего никого не проверяла.

**Как решено.** Единая авторизация с ролями `user` / `admin`: `scrypt` для
паролей, сессии в SQLite, HttpOnly-cookie, ограничители частоты на вход и
регистрацию. Админка проверяет роль и на клиенте, и на каждом запросе к
`/api/v1/admin/*`. Учётка администратора создаётся при первом запуске, пароль
печатается в консоль. Импорт CSV из Tamaris убран: данные теперь
предсобранный JSON, его кладут на диск, а не заливают через веб.

## 3. Модель данных

| Сайт | Как грузил данные |
|---|---|
| Конструктор | Всё внутри JS-бандла: 25 питомцев и 123 навыка захардкожены (в обфусцированном виде — числа записаны шестнадцатеричной арифметикой вида `0x141`) |
| Tamaris (старая схема) | Тянул CSV в браузер: `rank_achievement_detail.csv` — **6.2 МБ**, `rank_player.csv` — 1.9 МБ |
| Tamaris (схема в архиве) | Уже переехал на предсобранные JSON: `manifest.json` → `servers/<id>/*.json` → `players/<id%1000>/<id>.achievements.json` |
| coddb.app | `api/heroes.json` + серверные API, которые в зеркало не попали |

**Как решено.** Везде вторая схема — статичные JSON под `/data`, грузятся по
требованию. Данные питомцев и навыков **извлечены из бандла конструктора**
(Playwright открыл зеркало, снял `window.__warpetOptimizerAPI.skills`) и
разложены в `pets.json` и `pet-skills.json` — теперь у вкладок «ТОП питомцев»
и «База навыков» есть нормальный источник, не зависящий от бандла. Сам
конструктор при этом продолжает читать свои данные изнутри себя.

CSV в браузер больше не грузится нигде.

## 4. Навигация

| Сайт | Что было |
|---|---|
| coddb.app | Боковое меню + верхняя панель. `optimizer.js` их **принудительно прятал** на `/warpets`: `#__next nav, #__next aside { display: none !important }` |
| Конструктор | Своя мини-навигация на два вида — «Билдер» и «ТОП питомцев» — внутри одной страницы |
| Tamaris | Плоский список из 7 пунктов + отдельная нижняя панель на мобильных |

**Расхождение:** три разные модели навигации, причём конструктор активно
ломал навигацию сайта, на котором стоял.

**Как решено.** Один навбар с шестью категориями и выпадающими меню
(Питомцы / База данных / Калькуляторы / Статистика / Сообщество / Аккаунт),
на мобильных — раскрывающееся меню по кнопке. Внутренняя навигация
конструктора («Билдер» / «ТОП питомцев») оставлена как есть: это переключение
видов внутри страницы, а не навигация по сайту.

## 5. Калькуляторы — единственное место, где поведение может отличаться

Логика калькуляторов coddb.app **не сохранилась** (см. раздел 0). Пять
калькуляторов написаны заново по открытым формулам игры:

* обучение войск — ресурсы, базовое время, время с бонусом скорости;
* лечение — доля от стоимости обучения (по умолчанию 30 %) и время;
* ускорения — сумма по номиналам и остаток/нехватка;
* ресурсы — время сбора, число ходок, время с дорогой;
* прокачка героев — медали по звёздам и опыт по уровням.

Все коэффициенты — стоимость юнита по тирам, секунды на юнита, доля лечения,
таблица медалей — вынесены в поля ввода, их видно и можно поправить под свою
версию игры. На каждой странице стоит явная пометка, что формулы переписаны.

Это единственный раздел, где числа могут разойтись с оригиналом. Все
остальные — конструктор, база героев, статистика — работают на исходных
данных и исходном коде.

## 6. Конструктор питомцев: что именно сохранено

Движок урона (`_0x106dd5` в бандле) сидит внутри обфусцированного Next.js-кода
и в осмысленный вид не разворачивается. Поэтому страница встроена **как есть**,
в полноэкранном фрейме, а не переписана. Проверено вживую: выбор питомца
(Golden Roc) → BEST BUILD → Damage Factor 3216.24, DPS 321.62, 133 допустимых
билда из 13 кандидатов, потрачено 509 990 пет-коинов + 4 янтаря.

Работает без изменений:

* полный перебор BEST BUILD по итоговому Total Damage / DPS;
* режим «ЛУЧШЕЕ ЗА ВАШУ СУММУ» с бюджетом пет-коинов и разными уровнями навыков;
* закреплённый врождённый талант в первом слоте;
* лимит: не более 3 навыков на одну характеристику;
* зависимости Advanced/Intense → базовый навык;
* навыки за янтарь — всегда 4 уровень, бюджет не тратят;
* пресеты боя (Дуэль / Полевой бой / AOE лимит / В окружении), цели, атакующие, длительность цикла;
* галочка «Нужна контратака?» — по умолчанию выключена;
* вкладка «ТОП питомцев» внутри конструктора.

Добавлен один файл — `warpets/embed.js`. Он прячет дублирующийся переключатель
языка и рисует полоску возврата, когда `/warpets` открыт отдельной вкладкой.
Расчётов не касается.

## 8. Как вернуть потерянное

1. Снять зеркало `coddb.app` заново **с выполнением JavaScript** — скриптом
   `mirror.mjs` из `frontend.zip` (он работает через Playwright, а не HTTrack).
2. То же самое для `codfan.com`.
3. Артефакты положить в `public/data/artifacts.json` — вкладка «Артефакты»
   подхватит файл сама.
4. Формулы калькуляторов, если найдутся в новом зеркале, — в
   `public/static/js/pages/calc.js`, константы `TROOPS`, `SPEEDUPS`,
   `HERO_STARS`, `HERO_XP_PER_LEVEL` в начале файла.
