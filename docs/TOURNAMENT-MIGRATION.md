# Перенос первого турнира — отдельная задача

Источник требования: голосовое сообщение 08:57:56 (см. ТЗ на главную
страницу, раздел 10). Задача самостоятельная и не входит в объём готовности
одного баннера на главной странице.

## Кто нужен

Ответственный со стороны заказчика получает у **Хана**: адрес действующего
турнирного ресурса, исходники, данные, медиафайлы и перечень реально
работающих функций. Без этого перенос не начинается — сообщения Хану в
рамках подготовки ТЗ не отправлялись.

## Порядок работ

1. Зафиксировать страницы, данные и функциональность текущего турнирного
   ресурса (снять зеркало / выгрузку, как это уже делалось для coddb.app —
   см. `docs/LOGIC-DIFFERENCES.md` для примера того, что может не пережить
   перенос).
2. Сделать резервную копию перед переносом.
3. Развернуть раздел `/tournament` внутри этого проекта и перенести
   существующее содержимое (сетки, участников, матчи, результаты — в том
   виде и объёме, в котором они реально существуют; без новой турнирной
   системы, регистрации, оплаты или автоподсчёта).
4. Подключить общее оформление, шапку, навигацию и подвал сайта
   (`public/static/js/app.js`, `public/static/css/kraken.css`).
5. Проверить сохранность записей и работу всех перенесённых функций.
6. Проверить ссылки и медиа; если есть доступ к исходному ресурсу и требуется
   смена адресов — настроить перенаправления со старых адресов.

## Текущее состояние на сайте

До завершения переноса `/tournament` показывает только статус «Раздел
готовится» из `public/data/content/tournament.json` (`status: "preparing"`),
без неработающей кнопки перехода. Когда данные будут перенесены, переключите
`status` на `"ready"` и подключите реальную страницу турнира — сетки,
участников и результаты в отдельном модуле
(`public/static/js/pages/tournament.js` — уже принимает `status: "ready"`,
контент турнирных данных нужно добавить по итогам переноса).
