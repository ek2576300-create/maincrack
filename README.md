# Хроники Кракена 888 / Kraken Chronicles 888

Четыре сайта, объединённые в один. За основу дизайна и логики взят **конструктор
питомцев** (`coddb.app/warpets` + `optimizer.js` v6, Kraken-стиль) — его палитра,
панели, баннер и элементы управления распространены на все вкладки.

---

## Запуск

Нужен **Node.js 22.5 или новее** (используется встроенный модуль `node:sqlite`).
Внешних зависимостей нет — `npm install` выполнять не нужно.

```bash
node server/server.mjs
```

Откройте `http://localhost:8888`.

При первом запуске создаётся администратор, его логин и пароль печатаются в консоли:

```
email:    admin@kraken888.local
password: kraken888
```

**Смените пароль сразу после первого входа** (Профиль → Сменить пароль), либо
задайте свои значения ещё до первого старта:

```bash
KC_ADMIN_EMAIL=you@example.com KC_ADMIN_PASSWORD='ваш-пароль' node server/server.mjs
```

### Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `8888` | Порт HTTP-сервера |
| `HOST` | `0.0.0.0` | Интерфейс |
| `KC_ORIGIN` | `http://localhost:$PORT` | Канонический адрес: подставляется в `canonical`, OG-теги, `sitemap.xml` и `robots.txt`. **На боевом домене обязательно задайте** (`https://ваш-домен.ru`) |
| `KC_DATA_DIR` | `server/data` | Где лежит база SQLite |
| `KC_ADMIN_EMAIL` / `KC_ADMIN_PASSWORD` | `admin@kraken888.local` / `kraken888` | Учётка администратора при первом запуске |
| `KC_YT_CHANNEL_URL` | `https://www.youtube.com/@Kraken_Chronicles` | Канал, чья лента показывается на главной и в `/videos` |
| `KC_YT_CHANNEL_ID` | — | `UC…`-идентификатор канала. Если задан, сервер не ходит на страницу канала, чтобы его определить |
| `KC_YT_TTL_MINUTES` | `60` | Как часто перечитывать RSS канала |
| `KC_YT_TIMEOUT_MS` | `8000` | Таймаут запроса к YouTube |
| `KC_YT_API_KEY` | — | Ключ YouTube Data API v3. Нужен только скрипту импорта (`scripts/import-youtube.mjs`), чтобы вытащить **весь** архив канала, а не последние 15 роликов |

### Боевой запуск

```bash
KC_ORIGIN=https://ваш-домен.ru PORT=8888 node server/server.mjs
```

Ставьте перед ним nginx/Caddy с TLS и прокидывайте `X-Forwarded-For` — сервер
читает этот заголовок для определения IP.

Пример unit-файла systemd:

```ini
[Unit]
Description=Kraken Chronicles 888
After=network.target

[Service]
WorkingDirectory=/srv/kraken888
Environment=KC_ORIGIN=https://ваш-домен.ru
Environment=PORT=8888
ExecStart=/usr/bin/node server/server.mjs
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

## Конструктор питомцев

Оригинальная страница `/warpets` встроена **как есть**, в полноэкранном фрейме.
Ничего в движке урона не менялось: `_0x106dd5` (расчёт Total Damage / DPS),
полный перебор BEST BUILD, режим «ЛУЧШЕЕ ЗА ВАШУ СУММУ» с бюджетом пет-коинов,
закреплённый врождённый талант, лимит 3 навыка на характеристику, зависимости
Advanced/Intense и галочка контратаки работают ровно как раньше.

Единственное, что добавлено — `warpets/embed.js`: он прячет дублирующийся
переключатель языка внутри конструктора (в шапке сайта уже есть свой), а при
открытии `/warpets` отдельной вкладкой рисует полоску возврата на сайт.

Конструктор доступен напрямую по `http://localhost:8888/warpets`.

## Чат поддержки и админка

Кнопка **«Выслушаем ваши идеи»** висит справа снизу на всех вкладках. Писать
может кто угодно, регистрация не нужна — гость опознаётся по cookie `kc_guest`,
так что переписка переживает перезагрузку страницы. Если гость потом
зарегистрируется, его старая ветка автоматически привязывается к аккаунту.

Сообщения падают в **Админка → Обращения**. Администратор видит диалог,
отвечает прямо оттуда, ставит статус (Открыто / Отвечено / Закрыто) и удаляет
ветку. Ответ появляется у пользователя в том же виджете (виджет опрашивает
сервер раз в 25 секунд), с красным счётчиком непрочитанных на кнопке.

**Админка → Пользователи** показывает всех: email, ник и сервер в игре, дату
регистрации, последний визит, число заходов и последний IP. Оттуда же можно
выдать или снять роль администратора, заблокировать (сессии сбрасываются
сразу) или удалить аккаунт.

**Админка → Обзор** — счётчики пользователей, сессий, обращений и посещений,
графики посещений и регистраций по дням, список популярных страниц.

## SEO

`<head>` собирается на сервере под каждый роут, до выполнения JavaScript, — то
есть краулер видит готовый `title`, `description`, `keywords`, `canonical`,
`hreflang` (ru/en/x-default), Open Graph, Twitter Card и три блока JSON-LD
(`WebSite` с `SearchAction`, `WebApplication` для конструктора, `BreadcrumbList`).
В `<noscript>` кладётся заголовок, описание и полная карта ссылок, чтобы
страница несла текст и без JS.

Ключевые слова заданы в `public/static/js/routes.js` — `SITE.keywords` идут на
каждую страницу, `SEO['/путь'].keywords` добавляются к ней. Базовый пул:

> хроники кракена 888, хроники кракена, кракен 888, kraken chronicles 888,
> kraken chronicles, kraken 888, Кraken Chronicles, альянс кракен 888,
> сервер 888 call of dragons, call of dragons, cod db, конструктор питомцев,
> war pet builder, лучший билд питомца, калькулятор call of dragons,
> tamaris war stats, рейтинг альянсов, топ игроков сервера

`robots.txt` и `sitemap.xml` (с `hreflang`-альтернативами) отдаются сервером,
адреса в них берутся из `KC_ORIGIN`.

Чтобы добавить ключи — правьте `SITE.keywords` в `routes.js`. Один файл, и
навигация, и SEO обновятся вместе.

| `GET  /api/v1/admin/overview` | админ | Счётчики и графики |
| `GET  /api/v1/admin/users` | админ | Список пользователей |
| `PATCH /api/v1/admin/user` | админ | Роль и блокировка |
| `DELETE /api/v1/admin/user` | админ | Удалить пользователя |
| `GET  /api/v1/admin/threads` | админ | Список обращений |
| `GET  /api/v1/admin/thread` | админ | Одно обращение |
| `POST /api/v1/admin/reply` | админ | Ответить |
| `PATCH /api/v1/admin/thread` | админ | Статус |
| `DELETE /api/v1/admin/thread` | админ | Удалить |

Пароли — `scrypt` (N=16384, r=8, p=1) с индивидуальной солью. Сессии — HttpOnly
cookie `kc_session`, срок 30 дней, хранятся в SQLite. На регистрацию, вход и
отправку сообщений стоят ограничители частоты.

## Лента YouTube-канала

Вкладка **Хроники Кракена → Видео канала** (`/videos`) и блок на главной берут
список из `GET /api/v1/youtube/videos`. Сервер:

1. определяет `channelId` канала (или берёт готовый из `KC_YT_CHANNEL_ID`);
2. читает публичный RSS `youtube.com/feeds/videos.xml?channel_id=…` —
   это последние 15 роликов с названием, датой, описанием, обложкой и
   просмотрами;
3. сливает их с `public/data/site/videos.json`, где лежит полный архив и
   ручные поля (теги, свой заголовок, закрепление, скрытие);
4. кэширует последний удачный ответ в `$KC_DATA_DIR/youtube-cache.json`,
   поэтому без интернета сайт показывает прошлую ленту, а не ошибку.

Если YouTube недоступен, страница не ломается: под лентой честно пишется
источник и причина («YouTube недоступен: …»).

**Полный архив канала** (не только последние 15) заливается скриптом:

```bash
node scripts/import-youtube.mjs                  # RSS, последние 15
KC_YT_API_KEY=... node scripts/import-youtube.mjs  # Data API v3, весь канал
node scripts/import-youtube.mjs --dry-run         # посмотреть, ничего не писать
```

Скрипт дописывает `public/data/site/videos.json`, сохраняя ручные поля
существующих записей. Удобно повесить его в cron раз в сутки.

Видео проигрывается прямо на странице (`youtube-nocookie.com`), и до клика по
обложке ни один скрипт YouTube не загружается.

## Проверка фронтенда

Сборки нет, модули грузятся браузером как есть, поэтому опечатка в импорте
видна только в рантайме — страница не рисуется и в консоли висит
`does not provide an export named …`. Чтобы ловить это заранее:

```bash
node scripts/check-imports.mjs
```

Скрипт проходит по всем файлам `public/static/js`, разбирает именованные
импорты и проверяет, что такой экспорт в целевом модуле действительно есть.
Возвращает ненулевой код, если что-то не сходится — удобно в pre-commit или CI.

Вторая проверка — про общие хелперы, которые принимают функцию перевода
позиционным аргументом (`newsCard(n, lang, t, link)`, `hofCard(person, lang, t)`,
`videoCard(v, lang, t)`, `sourceNote(data, t, lang)`, `counted(shown, total, t, lang)`,
`serverSelect(servers, onChange, t)` и секции главной):

```bash
node scripts/check-args.mjs
```

Стоит вызвать такой хелпер в «привычном» порядке или забыть аргумент — и `t`
уезжает в соседний слот. Браузер тогда валит всю вкладку, а роутер показывает
`Не удалось загрузить данные — /путь — t is not a function`, по которому без
консоли не понять, где именно сломалось. Скрипт сопоставляет каждый вызов с
объявлением (локальным или импортированным) и требует `t` ровно в том слоте,
где он объявлен. Тоже возвращает ненулевой код для CI.

## Обновление данных

**Статистика серверов.** Замените файлы в `public/data/webdata/` (структура
описана в `README_WEBDATA.md` исходного проекта Tamaris) — сайт подхватит их
без пересборки, кэш на этих файлах всего 5 минут.

**Питомцы, навыки, герои.** `public/data/pets.json`, `pet-skills.json` и
`heroes.json` вытащены из бандла конструктора и из `api/heroes.json`. Если
обновится игровая база — снимите зеркало заново скриптом `mirror.mjs` из
исходного `frontend.zip` и перегенерируйте эти три файла.

**Логотипы и фавикон.** Исходная графика лежит в
`public/static/img/brand/src/`: `mark.jpg` — круглая эмблема, `banner.jpg` —
широкий баннер. Всё остальное собирается из них:

```bash
npm i --no-save sharp && node scripts/build-brand.mjs
```

Скрипт вырезает эмблему по кругу (в исходнике углы белые), раскладывает её
по размерам иконок, собирает `public/favicon.ico`, режет баннер под `srcset`
и клеит обложку 1200×630 для соцсетей. Готовые файлы в репозитории, так что
для запуска сайта `sharp` не нужен — он нужен, только когда меняют графику.
